# Notes and Self-Improvement

## Research memory versus process memory

Research truth belongs in published result cards, findings, lines, campaigns, and manuscript state.

Notes capture reusable process, method, resource, or human-preference lessons that improve future decisions. They are not a second trial log.

## Note rule

Write a note only if a future agent would make a better decision because of it. Cite source paths and mark active or superseded status.

Do not write notes for routine commands, raw logs, repeated report summaries, or facts that belong in canonical research state.

## Instruction patch proposals

If a recurring workflow defect indicates an instruction change:

1. write a proposal under `research_trajectory/instruction_patches/`;
2. cite multiple examples or a high-severity failure;
3. include proposed text, benefits, risks, and tests;
4. do not edit managed instructions during the trial;
5. promote only through explicit review and managed template release.
